    ==

    本文档是 2014 年撰写的课程 “A Client/Server Example - AngularJS 1.x / Spring 4”的后续。原文档使用 Spring 4 / Spring Data / Spring MVC 服务器和 AngularJS 1.x 客户端构建了一个小型医疗预约日程应用（“[RdvMedecins]”）。

    十二年后，所用的两个框架都有了显著演进，甚至在常见使用中已被取代：

    • 在服务器端，[NestJS] 已成为构建结构化 Web 应用最广泛使用的 Node.js/TypeScript 框架之一，其理念与 Spring 相近（模块、控制器、服务、依赖注入），但处于 JavaScript/TypeScript 生态之中；
    • 在客户端，AngularJS 1.x 自 2016 年起被彻底重写，并更名为 [Angular] （版本 2、4、5……直至版本 22）——这是本课程 [Angular] / [NestJS] 变体所采用的方式。本文档采用另一种更为彻底的方式：[React] （由 Meta 于 2013 年创建），它是一个界面库而不是完整的框架，其中每个组件都是一个简单的 JavaScript/TypeScript 函数（见第 4 章）。

    本文档的目的是重温最初的案例研究——同样的应用、同样的功能、同样的数据库——并 重新构建它 使用当前的工具，同时尽可能保持与 2014 年文档相同的教学进度。

    1.1. 分步重建

    原文档约有 300 页，除应用的核心功能——基于角色的身份验证（Spring Security）——之外，还包含十二个循序渐进的示例，用于分步学习 AngularJS 1.x。一次性重建全部内容既耗时又难以消化。

    因此，本文档涵盖重建的 前两步：

    • 应用的总体架构（原则上不变）；
    • 数据库（保持不变，只是增加了 [users] 表）；
    • 完整的 [NestJS] 服务器，具备查看以及预约/取消预约的全部功能；
    • 基于令牌的身份验证（JWT）和基于角色的访问控制 （ADMIN/USER），相当于原文档中的 Spring Security 层；
    • 相应的 [React] 客户端，具有相同的功能、一个登录界面、一个根据已登录用户角色定制的 Bootstrap 界面，以及在法语和英语之间切换界面的能力（[i18next]/[react-i18next]）。

    原文档中的两项功能在本阶段未包含在本文档中：原客户端的“调试”模式（显示当前视图的原始模板），已在此次移植中 有意地 省略（这一决定的理由见第 6 章），以及人为网络延迟的配置，已推迟到后续阶段。

    1.2. 本文档面向的读者

    本文档不要求事先了解 [NestJS] 或 [React]。每个新概念（装饰器、依赖注入、组件、Hook 等）在出现时都会尽可能详细地加以解释——即使对从未写过一行 TypeScript 的读者也是如此。

    不过，具备一些基础知识有助于更好地学习本文档：

    • 对 JavaScript 语言有基本了解（变量、函数、数组、对象）；
    • 对 Web 应用中的 HTTP 交互有基本了解（GET/POST 方法、JSON 格式）；
    • 常见的 HTML 标签；
    • 使用命令行（cd、npm install……）。

    您无需事先熟悉 TypeScript 语言（服务器端和客户端都会用到）：它是 JavaScript 的超集，增加了类型系统，文档中每当用到时都会加以解释。感兴趣的读者可以参阅文档 [Introduction to the TypeScript Language and the NestJS Framework (2026)]，其中详细讲解了 TypeScript。

    1.3. 应用架构

    自原文档以来，应用的总体架构没有改变：

    • Web 服务器提供一个单独的 HTML 页面以及唯一的 CSS/JS，其中包含一个基于 [React] 应用，采用 组件模型（视图 + 相关逻辑），并依靠 服务 与服务器通信；
    • 用户与浏览器中显示的视图交互。用户的操作有时需要向 [NestJS] 服务器发出请求，服务器处理请求并返回 JSON （JavaScript Object Notation）响应；该响应用于更新呈现给用户的视图。

    所讨论的应用将具有如下架构：

    • 在 [1] 中，[React] 应用的用户向该应用的 [presentation] 层 [2] 发出请求；
    • 为了执行用户请求的操作，[presentation] 层 [2] 可能会查询 [Services] 层 [3]；
    • 为了提供所请求的服务，[3] 层可能需要查询 [4]，即由 [NestJS] 实现的远程 JSON 服务器；
    • 根据在 [5] 中收到的请求，可能会查询 [6-8] 层；
    • 服务器的响应按相反顺序返回经过 [2-8] 层；
    • 显示给用户的视图 [1] 反映该响应；

    注：如果您对项目的架构感到困惑，请回头参阅此图。请注意，DBMS 由服务器处理，而不是由客户端处理。

    1.4. 使用的工具

    本文档使用以下工具（其安装在第 1 章中详细说明）：

    • Node.js （22 或更高版本）及其包管理器 npm——在 JavaScript 生态中，相当于原 Spring 服务器所用的 Java + Maven；
    • Visual Studio Code，一款免费的代码编辑器，带有其 TypeScript 扩展——相当于原文档中使用的 Spring Tool Suite（STS）和 WebStorm；
    • [NestJS] CLI （[@nestjs/cli]），一个命令行工具，用于生成服务器项目结构并启动其开发服务器；在客户端，[Vite] 无需全局安装——可以直接通过 npm 在本文档附带的项目上使用；
    • [MySQL] 8 用于数据库（原文档使用的是 [MySQL] 5——关系模式本身保持不变）；
    • Postman （或任何其他 HTTP 客户端），用于测试服务器上响应 POST 请求的 URL（/addAppointment、/deleteAppointment）——浏览器只能测试 GET 请求。

    1.5. 应用功能

    [RdvMedecins] 应用的“业务”功能与原文档相比 保持不变；不过，访问控制比原文档略为稳健（见下表）：

    • 一家医疗诊所聘有多名医生，每位医生都有各自的问诊时间段；
    • 用户必须登录（用户名/密码）才能访问应用；
    • 登录后，用户可以选择医生和日期，并查看该医生当天的日程：每个时间段显示为可预约或已被预约；
    • 角色为 ADMIN 的用户还可以为其选择的患者预约一个可用的时间段，并取消已有的预约；
    • 角色为 USER 的用户可以查看日程，但不能预约或取消（只读访问）——这是与原文档有意设置的差异，在原文档中，角色 USER 仅用于演示拒绝访问，根本无法查看任何内容（这一选择的理由见第 3 章“身份验证”一节）。
