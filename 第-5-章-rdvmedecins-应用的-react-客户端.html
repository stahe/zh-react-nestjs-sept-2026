    6. 第 5 章 - [RdvMedecins] 应用的 [React] 客户端

    本章逐个文件详细介绍本文档附带的 [rdvmedecins-react-client] 文件夹的内容，采用本课程一贯的格式：逐行编号的源代码，后面是“我们来解读这段代码：”一节。项目中的每个文件夹也都包含自己的 [README.md]。

    6.1. 架构概览

    与原文档一样，客户端遵循分层架构，我们在这里称之为 V-Services（视图-服务）：

    术语上有一点差异值得注意：在 AngularJS 1.x 中，视图（HTML 模板）和控制器（相关联的 JavaScript 类）是两个独立的实体，通过 $scope 相连。在 [React] 中，它们合并为单个实体，即 组件 （见上一章）——与 [Angular] 中完全一样，尽管形式不同（是函数而不是类）——因此，在下文中，原文档区分视图和控制器的地方，我们将统称为“组件”。

    与原文档一样，组件绝不直接与服务器通信：这一职责专属于服务层（这里是 Hook useAppointmentService() 和上下文 AuthContext）。这是一条设计原则，同样适用于 AngularJS 1.x 以及 [Angular] 和 [React]——它没有改变。

    6.2. 项目结构树

    这种划分直接遵循原文档的流程（登录、选择医生/日期、显示日程表、预约），只是在这里组织为 [React] 函数组件，而不是 AngularJS 1.x 的独立控制器/视图，或 [Angular] 的独立组件。与本课程 [Angular] 的目录结构相比，有两处结构上的差异：

    • 根组件由 三个 文件（App.tsx、App.css、README.md）组成，而不是五个（app.ts、app.html、app.css、app.config.ts、app.routes.ts）：[JSX] 把类和模板合并在一起，并且 [React] 没有与 app.config.ts 对应的应用配置文件（见下文的“应用配置”）；
    • 出现了一个 `core/context/` 文件夹，它在 [Angular] 变体中是没有的：它包含自定义 Hook 和 [React] [Context] 文件 ，它们充当 [SettingsService]、[AuthService]、[LanguageService] 等可注入服务（属于 [Angular] 变体）——这一机制（Hook + [Context]）已在上一章中连同一个通用示例一起介绍过（见上一章的“共享逻辑”）。

    [Bootstrap] 5 用于所有视图（在 main.tsx 中导入；见下文）——这是 Bootstrap 3 的直接演进（原文档已使用 Bootstrap 3），并且与本课程的 [Angular] 变体保持一致。

    • 第 12–19 行："dependencies": { … } ——在浏览器中运行应用所需的包：[react]/[react-dom]（[React] 的核心及其与浏览器 DOM 的集成）、[Bootstrap] （仅样式表），以及——本章新增的——[i18next]/[i18next-http-backend]/[react-i18next]，即用于界面 FR/EN 翻译的第三方库（见下文的 i18n.ts 和 core/context/language.context.tsx）。与本课程的 [Angular] 变体不同，这里没有与 [@angular/router] 对应的包（没有 路由器；见上一章），也没有 RxJS（[fetch] 直接返回 Promise；见上一章）；
    • 第 20–26 行："devDependencies": { … } ——仅在开发期间需要的包，绝不会包含在交付给浏览器的最终包中：TypeScript 和 [React] 的类型（[@types/react]、[@types/react-dom]——[React] 本身是用 JavaScript 而不是 TypeScript 编写的，不同于 [Angular]）、[@vitejs/plugin-react] （把 [JSX] 转换为 JavaScript，并在开发期间提供 Fast Refresh）、TypeScript，以及 [Vite] 本身。

    与 [NestJS] 服务器（[commonjs] 模块，见第 3 章）不同，这个项目运行在原生的 ECMAScript 模块（import/export）上——与本课程的 [Angular] 变体完全一样（tsconfig.json 中的 “module”: “preserve”，见下文）。

    • 第 6 行："strict": true, ——与本课程 [tsconfig.json] 中 [Angular] 变体的配置一样，启用了 TypeScript 的完整严格模式：每个变量都必须具有可确定的类型，每个 null 或 undefined 值都必须被显式处理；
    • 第 7–8 行："noUnusedLocals": true, "noUnusedParameters": true, ——在编译期间标记任何已声明但从未使用的变量或参数——本课程的 [Angular] 变体没有显式启用这一设置（[Angular] 编译器通过 strictTemplates 有自己不同的检查）；

    本课程的 [Angular] 变体把 [tsconfig.json] （公共基础）和 [tsconfig.app.json] （通过项目引用机制）分开，而这个较小的 [React] 项目只有一个文件——因为无论如何，模板的类型检查（[Angular] 和 strictTemplates）在这里都没有对应物：检查 [JSX] 的是 TypeScript 编译器本身，就像检查任何其他 .tsx 文件一样。

  .use(initReactI18next)

    fallbackLng: 'en',

    },
  });

    我们来解读这段代码：

    • 第 6 行：.use(HttpBackend) ——通过 HTTP GET 请求加载每个字典，URL 由 [backend.loadPath]（第 15 行）构成：[/i18n/fr.json] 或 [/i18n/en.json]，与 [TranslateHttpLoader] 在 [Angular] 方面构成的 URL 完全相同（prefix: '/i18n/'，suffix: '.json'），因此 [public/i18n/fr.json] 和 [public/i18n/en.json] （见下文）可以原样复用，无需任何修改；
    • 第 7 行：.use(initReactI18next) ——把 [i18next] 接入 [React]：提供 features/ 中每个组件使用的 useTranslation() Hook，以及 React 的 Hook [Context] （库内部使用，这里看不到），语言变化时它会触发整个界面的完全重新渲染——相当于 [Angular] 方面由 [TranslatePipe] 装饰器与 [provideTranslateService(...)] 结合起来所完成的功能；
    • 第 9 行：lng: navigator.language?.toLowerCase().startsWith('fr') ? 'fr' : 'en', ——启动语言（浏览器设置为法语时为法语，否则为英语；第 10 行有 fallbackLng: 'en'）；Hook [useLanguage()] （见下文的 core/context/language.context.tsx）会立即用 localStorage 中存储的选择（如果有的话）替换它——与 [app.config.ts] 在 [Angular] 方面的 lang: 'en' 完全一样；
    • 第 11–13 行：interpolation: { escapeValue: false, }, ——[React] 本身已经对 HTML 进行了转义（防范 XSS 漏洞）：无需再让 [i18next] 再转义一次。

    在原文档（2014）中，AngularJS 1.x 客户端依靠 angular-translate 库满足同样的需求——它在 AngularJS 1.x 生态中是 [@ngx-translate/core] （本课程 [Angular] 变体使用的库）的前身，在这里则是 [i18next] 的前身。这两个现代库（[ngx-translate] 在 [Angular] 方面，[i18next] 在 [React] 方面）都通过简单的 HTTP GET 请求加载 JSON 字典，采用相同的“每种语言一个文件，每个界面一个分区”的模式。

    • 第 44 行：aria-label={t('BOOKING_DIALOG.CLOSE_ARIA')} ——不同于 [attr.aria-label="'BOOKING_DIALOG.CLOSE_ARIA' | translate"] 在 [Angular] 方面的写法（一种有别于 {{ }} 插值的属性绑定），[JSX] 不区分 HTML 属性和元素的内容：{expression} 在两处的用法完全相同。

    与 [Angular] 方面一样，这个组件使用模态框的真正类，但其可见性由 [React] 控制（基于 [open] 属性的条件渲染），而不是由 [Bootstrap] 的 JavaScript 控制（[bootstrap.bundle.js, new bootstrap.Modal(...)]）——以防止 [Bootstrap] 和 [React] 各自独立地管理同一条信息（模态框是否打开？），这是一个常见的微妙缺陷来源。原文档（2014）使用了 angular-ui-bootstrap 库中的组件（一个“交钥匙”式的 AngularJS 1.x 模态框），它已经是按照这同一原则设计的。

    import { useEffect, useRef, useState } from 'react';
import { useTranslation } from 'react-i18next';
import { useAuth } from './core/context/auth.context';
import { useSettings } from './core/context/settings.context';
import { useLanguage } from './core/context/language.context';
import { useAppointmentService } from './core/services/appointment.service';
import type { DoctorDaySchedule, Client, SlotJson, Doctor, AppointmentJson } from './core/models/appointment.models';
import { DoctorDayPicker } from './features/doctor-day-picker/DoctorDayPicker';
import { Schedule } from './features/schedule/Schedule';
import { BookingDialog } from './features/booking-dialog/BookingDialog';
import { Login } from './features/login/Login';
import './App.css';

export function App() {
  const { t } = useTranslation();
  const auth = useAuth();
  const settings = useSettings();
  const language = useLanguage();
  const api = useAppointmentService();

  const [doctors, setDoctors] = useState<Doctor[]>([]);
  const [clients, setClients] = useState<Client[]>([]);
  const [schedule, setSchedule] = useState<DoctorDaySchedule | null>(null);
  const [error, setError] = useState<string | null>(null);
  const [slotBeingBooked, setSlotBeingBooked] = useState<SlotJson | null>(null);

  const lastDoctorId = useRef<number | null>(null);
  const lastDay = useRef<string | null>(null);

  useEffect(() => {
    if (auth.isLoggedIn) {
      loadInitialLists();
    }
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [auth.isLoggedIn]);

  function loadInitialLists(): void {
    api.getAllDoctors().then(setDoctors)
      .catch((err: unknown) => setError(String((err as Error).message ?? err)));
    api.getAllClients().then(setClients)
      .catch((err: unknown) => setError(String((err as Error).message ?? err)));
  }

  function onLogout(): void {
    auth.logOut();
    setDoctors([]); setClients([]); setSchedule(null);
    setError(null); setSlotBeingBooked(null);
    lastDoctorId.current = null; lastDay.current = null;
  }

  function onSearchSchedule(criteria: { doctorId: number; day: string }): void {
    setError(null);
    lastDoctorId.current = criteria.doctorId;
    lastDay.current = criteria.day;
    loadSchedule();
  }

  function onBookingRequest(slot: SlotJson): void {
    setSlotBeingBooked(slot);
  }

  function onConfirmBooking(choice: { clientId: number }): void {
    if (slotBeingBooked === null || lastDay.current === null) {
      return;
    }
    api.addAppointment(lastDay.current, choice.clientId, slotBeingBooked.id)
      .then(() => { setSlotBeingBooked(null); loadSchedule(); })
      .catch((err: unknown) => setError(String((err as Error).message ?? err)));
  }

  function onCancelAppointment(appointment: AppointmentJson): void {
    api.deleteAppointment(appointment.id).then(() => loadSchedule())
      .catch((err: unknown) => setError(String((err as Error).message ?? err)));
  }

  function loadSchedule(): void {
    if (lastDoctorId.current === null || lastDay.current === null) {
      return;
    }
    api.getDoctorScheduleOfDay(lastDoctorId.current, lastDay.current).then(setSchedule)
      .catch((err: unknown) => setError(String((err as Error).message ?? err)));
  }

  return (
    <div className="container py-4">
      <nav className="navbar navbar-expand-sm navbar-dark bg-primary rounded mb-4 px-3">
        <span className="navbar-brand mb-0">{t('APP.TITLE')}</span>
        <div className="d-flex align-items-center gap-2">
          <div className="btn-group btn-group-sm" role="group" aria-label="FR / EN">
            <button type="button" onClick={() => language.changeLanguage('fr')}
              className={'btn ' + (language.currentLanguage === 'fr' ? 'btn-light' : 'btn-outline-light')}>FR</button>
            <button type="button" onClick={() => language.changeLanguage('en')}
              className={'btn ' + (language.currentLanguage === 'en' ? 'btn-light' : 'btn-outline-light')}>EN</button>
          </div>
          {auth.isLoggedIn && (
            <>
              <span className="badge text-bg-light text-primary">{auth.role}</span>
              <span className="text-white">{auth.name}</span>
              <button type="button" className="btn btn-sm btn-outline-light" onClick={onLogout}>
                {t('APP.LOGOUT')}
              </button>
            </>
          )}
        </div>
      </nav>

      <div className="row g-2 align-items-center mb-4">
        <div className="col-auto">
          <label className="form-label mb-0" htmlFor="input-server-url">{t('APP.SERVER_URL_LABEL')}</label>
        </div>
        <div className="col-sm-4">
          <input id="input-server-url" type="text" className="form-control form-control-sm"
            defaultValue={settings.apiBaseUrl} onChange={(e) => settings.setApiBaseUrl(e.target.value)} />
        </div>
      </div>

      {error && <div className="alert alert-danger" role="alert">{error}</div>}

      {!auth.isLoggedIn ? (
        <Login />
      ) : (
        <>
          <DoctorDayPicker doctors={doctors} onSearch={onSearchSchedule} />
          <Schedule schedule={schedule} canEdit={auth.isAdmin}
            onBook={onBookingRequest} onCancel={onCancelAppointment} />
          <BookingDialog open={slotBeingBooked !== null} slot={slotBeingBooked}
            clients={clients} onConfirm={onConfirmBooking} onClose={() => setSlotBeingBooked(null)} />
        </>
      )}
    </div>
  );
}

    我们来解读这段代码：

    • 第 27–28 行：const lastDoctorId = useRef<number | null>(null); const lastDay = useRef<string | null>(null); ——我们存储最近一次搜索（医生 + 日期），以便在预约或取消之后刷新日程表。使用的是 [useRef]()，而不是 [useState]()：这两个值从不直接用于显示（不同于“schedule”或“error”），因此它们变化时无需重新绘制组件——这与在 [Angular] 方面把 [lastDoctorId/lastDay] 保留为简单的私有字段而不是信号的理由完全相同；修改 [useRef]() 的值（.current = …）不会重新绘制组件，这不同于 [setXxx()] 来自 [useState]() 的调用；
    • 第 30–35 行：useEffect(() => { if (auth.isLoggedIn) { loadInitialLists(); } }, [auth.isLoggedIn]); ——每当 [auth.isLoggedIn] 变化时就重新执行其函数体——直接对应 [effect(() => { if (this.auth.isLoggedIn()) { … } })] 在 [Angular] 方面的写法。它在组件挂载时也会运行一次：如果会话已存储在 [localStorage] 中（页面重新加载），列表会在启动时立即加载，而无需等待登录；
    • 第 89–94 行：<div className="btn-group btn-group-sm" …> …FR…EN… </div> ——语言选择器始终可见（包括在登录界面上）；而角色徽章、姓名和登出按钮则仅在 [auth.isLoggedIn] 时才显示（第 95–103 行，[{auth.isLoggedIn && (…)})]——与 [Angular] 和 [(@if (auth.isLoggedIn()) { … })] 两侧的逻辑完全相同；
    • 第 119–130 行：{!auth.isLoggedIn ? ( <Login /> ): ( <>…</> )} ——只要 [useAuth().isLoggedIn] 等于 false，该组件就只显示 <Login />；由于现在所有服务器路由都受 [JwtAuthGuard] 保护（第 3 章），在登录之前加载医生/客户（患者）/日程表无论如何都没有意义（还会导致 401 错误）——理由与 [Angular] 完全相同；
    • 第 123–127 行：<DoctorDayPicker doctors={doctors} onSearch={onSearchSchedule} /> … ——features/ 中的三个“业务逻辑”组件在这里组装，每个都接收自己的 props（数据 + 回调函数）——完全对应 [app.html] 模板在 [Angular] 方面的写法，在那里同样的三个组件以 [doctors]="doctors()"（[search)="onSearchSchedule($event)"]……的形式出现。

    状态（[useState/useRef]）、副作用（[useEffect]）和事件处理函数（各个 onXxx 函数）：这恰好是上一章已经介绍过的四个组成部分，在这里应用于整个根组件——这个文件中没有引入任何新东西，只是把它们组装了起来。
